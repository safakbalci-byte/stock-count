
# 0002 - All changes must go through pull requests

## Context

Previously, contributors could make changes directly to the main branch. This made it difficult to review changes before they became part of the project. Mistakes could affect the main branch without being noticed.

## Decision

All changes must be submitted through pull requests. Contributors must create a separate branch, make their changes, and open a pull request for review before merging into the main branch.

## Consequences

- Changes can be reviewed before being merged.
- The main branch stays more stable and organized.
- Every change has a clear history and discussion.
- Mistakes can be identified before reaching the main branch.
- The process requires more steps and time because every change needs a pull request.
